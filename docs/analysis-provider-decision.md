# P0 真实分析服务：决策简报

## 已具备的前端契约

`analysis-engine.js` 只接收完整的如下对象，再将其交给播放器：

```js
{
  source: { kind: "ai", confidence: 0.78 },
  sections: [{ start, end, name, chord, register, density, lead, principle, moment, trace, next, cue, note }],
  tracks: [{ id, name, cn, icon, color, clips: [[start, duration, label]] }]
}
```

缺字段、无 AI 来源或置信度越界的结果都会被拒绝；界面继续显示“未分析”。

## 推荐：本地优先，后端可选

第一版建议在用户设备或自托管 worker 中处理音频，不把原始音频保存到应用数据库。服务只返回上述 JSON 与可选的匿名内容哈希。

| 决策项 | 推荐默认值 | 原因 |
| --- | --- | --- |
| 音频离开设备 | 否；只有用户明确选择云端加速时才上传 | 保住产品“诚实机制”的信任基础 |
| 原始音频保留 | 0 天 | 结果分享不需要分发受版权保护的音频 |
| 分析结果缓存 | 内容哈希 + JSON，30 天可清除 | 重复导入秒出，同时不保存音频 |
| 目标延迟 | 48 秒片段 ≤ 20 秒；全曲异步 | 前端已有分析中状态，不需要伪造即时结果 |
| 置信度阈值 | 每项单独报告；低于 0.60 不显示确定乐器/和弦结论 | “不确定”优先于不可靠的确定 |

## 实施顺序

1. **P0-A / 服务骨架**：定义 `POST /analysis` 或本地 worker 的流式进度协议；保存原始 provider 输出与规范化 JSON 的测试夹具。
2. **P0-B / 乐器与段落**：段落检测、Basic Pitch 转谱特征、乐器分类；返回轨道活动区间，不声称分离音源。
3. **P0-C / 和声解释**：把和弦、置信度和可解释证据分开返回；低置信度显示范围或“无法可靠判断”。
4. **P1 / 分轨真实化**：仅在 Demucs 或同类 separation 的试听结果存在时启用 M/S；分析轨道不能冒充可单独播放的 stem。
5. **P2 / 缓存与分享**：只分享分析卡片与可撤销的结果 JSON，不分享上传音频。

## 接口与安全验收

- 未配置 provider：继续 `unavailable`，不得产生网络请求。
- provider 失败、超时或返回不完整：继续播放原文件，显示失败原因，不显示任何推测轨道。
- 每个分析字段有独立置信度或明确标注“未知”。
- 服务日志不含原始音频、文件名或可识别内容；调试样本必须是授权样本。
- M/S 默认关闭，直到实际分离 stem 的时长、采样率和校验值通过。

## 需要确认的最小决策

已确认的策略：

> 原始音频默认不离开用户设备、不被保存；允许用户主动选择云端加速，云端只在分析期间临时处理音频并在任务结束后删除。

P0-A 已领取：本地 provider 以 `{ file, duration, reportProgress }` 接口接入；未配置本地分析器时仍明确显示“未分析”。

## 已决：真实乐器身份分类（2026-07-24）

已完成的本地 Basic Pitch、和弦与段落管线会把乐器身份明确标记为“未可靠识别”。这比由音高转录推断“钢琴/弦乐/贝斯/鼓”更诚实。

人工决策：**暂不安装任何乐器分类器**。候选的本地 Essentia 运行时及模型受 AGPLv3 许可约束，与本仓库 MIT 许可及 M3 开源演示目标冲突，确认不纳入此项目。乐器身份继续保持“未可靠识别”，不领取乐器身份 Gap。

未来仅当找到许可证兼容（MIT/Apache 类）的本地分类路径、并经新一轮人工批准后，才可重新开启该 Gap。
