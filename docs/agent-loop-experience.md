# Agent Loop 经验：把 Token 变成可信状态变化

## 一句话经验

Agent Loop 不是让模型持续工作，而是让它在契约、证据、预算和独立验证约束下，持续推动可保留、可回滚的状态跃迁。

## 已确认的经验

### 1. 产出单位必须是状态跃迁

报告、代码行数、运行时间和 Token 消耗都不是最终产出。有效产出只有：

- 消除一个真实 Gap；
- 证伪一个错误假设；
- 建立一个新的可靠 Validator；
- 将未知状态变成有证据的 PASS、FAIL 或 BLOCKED；
- 让人不需要阅读大部分过程。

### 2. 目标模糊时，自动化应探索而不是实施

产品页面、功能职责和用户价值尚未收敛时，只允许生成互斥、可比较的薄原型。不能让 Agent 把多个方向混成一个产品，也不能随机挑选一个方向长期编码。

### 3. 没有 Validator 的自治会放大错误

实现 Agent 擅长给自己的工作编写合理解释，因此实现者不能最终验收自己。Validator 必须从原始 Contract、基线、候选差异和可复现证据开始判断。

### 4. UNKNOWN 是合法且有价值的状态

数据不足时输出 UNKNOWN，比输出一份流畅但不可靠的分析更有价值。UNKNOWN 能阻止错误进入后续状态。

### 5. 异常压缩比定期长报告重要

人类应该只看到：

```text
系统状态
可信状态变化
需要人工决策
失败但有价值的结论
下一项候选动作
```

详细日志只在调查某个 Gap 时展开。

### 6. 自主运行必须默认不触碰生产

无人值守 Loop 可以读取、分析、实现候选、运行测试和独立验证，但默认不能部署、使用密钥、删除数据或改变产品方向。

### 7. `.cursor` 与 `loop/` 是不同层

- `.cursor` 保存角色、规则、技能和触发命令；
- `loop/` 保存跨 Agent、跨会话的事实、Gap、证据和判定；
- `AGENT_LOOP_CONTRACT.md` 是唯一政策源；
- 不在 Cursor Rule 中复制整份 Contract。

### 8. 进化对象首先是 Validator

当 Loop 效率不高时，优先：

1. 缩小 Gap；
2. 加强 Validator；
3. 固化失败为回归测试；
4. 降低触发频率；
5. 改善证据压缩。

不应先增加 Token、并行 Agent 数量或生产权限。

## ONSEKI 的适用方式

ONSEKI 适合在产品方向已确认的局部能力上持续自治，例如：

- 播放时钟与视觉同步；
- mute/solo 状态一致性；
- 键盘和无障碍行为；
- 响应式布局回归；
- 性能和构建问题；
- 分析置信度标签完整性。

以下内容不适合无人值守自动决定：

- 下一张核心页面的职责；
- 音乐解释应该采取哪种产品立场；
- 视觉语言的大幅改变；
- 对真实艺术家作品的分析结论；
- 生产发布和用户数据处理。

## 衡量 Loop 是否有价值

长期只跟踪：

- `verified_transition_rate`
- `human_override_rate`
- `rollback_rate`
- `validator_false_pass_rate`
- `median_attempts_per_gap`
- `median_human_reading_minutes`
- `no_change_rate`

如果 Token 增长而这些指标没有改善，应降低运行频率或停止 Loop。
